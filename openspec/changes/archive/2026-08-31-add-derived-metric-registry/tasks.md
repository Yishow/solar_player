## 7. Review findings: registry lifecycle, unit correctness, and consumer boundaries

- [x] 7.1 Enforce that `Disabling a derived metric retires its evaluation and materialized value`: the transaction that persists the disabled state also deletes the definition's `derived_metric_evaluations` and `live_metric_values` rows for every scope it produced, evaluation/definition reads stop returning disabled definitions to story and card consumers, and source topic identity-conflict validation keeps rejecting a mapping onto a disabled definition's scoped key (design: Retire disabled definitions from storage). Verify with `derivedMetricRegistryService.test.ts` asserting `readDerivedMetricEvaluation` returns null and the scoped live row is gone after disable, and `settings-mqtt.test.ts` asserting the conflict is still reported.
- [x] 7.2 Make registry compilation failures degrade without blocking service startup: compiling stored definitions partitions them into compiled and excluded sets, activates the compiled set, and records each exclusion with its definition key and validation reason, so a stored definition whose input metric disappeared no longer aborts `buildApp()` while explicit mutations stay strict and all-or-nothing (design: Fail soft on stored registry compilation). Verify with a registry test that compiles a stored state containing an unknown-input definition and asserts startup succeeds with that definition excluded and reported, plus an existing mutation test asserting an invalid proposed state is still rejected in full.
- [x] 7.3 [P] Extend `Unit compatibility is validated for additive operations` to magnitude: unit checking compares scale as well as dimension, evaluation applies the conversion when the declared output unit differs in scale from the inferred result, and an irreconcilable declaration is rejected so a kilogram-magnitude result is never published as tonnes (design: Normalize unit case and scale). Verify with `derivedMetricExpression.test.ts` cases for `kWh * kg/kWh` declared as `t` and as `kg`, and a parity case pinning the seeded CO2 output value.
- [x] 7.4 Make metric input units are normalized before evaluation hold in input resolution: unit strings match the known-unit table case-insensitively so a reading stored as `kwh` or `KW` resolves and converts instead of failing the node, and a reading with no recorded unit resolves as invalid input rather than being adopted into the input's declared unit (design: Normalize unit case and scale). Verify with `derivedMetricRegistryService.test.ts` cases covering a lowercase stored unit and a null stored unit.
- [x] 7.5 Make site-scoped definitions declare which sites they evaluate and apply it to the Factory Circuit totals: `factoryCircuit.jungliTotalPower` evaluates only under CL and `factoryCircuit.guanyinTotalPower` only under KN, definitions omitting the declaration still evaluate for every site, and no KN Jungli node or permanently unavailable CL Guanyin node is evaluated, materialized, or repeatedly deleted (design: Restrict per-site aggregates to declared sites). Verify with `derivedMetricRegistryService.test.ts` asserting the materialized scoped key set after evaluation.
- [x] 7.6 Make `Evaluation is triggered from dependency changes and is deterministic` incremental at ingestion: an inbound metric update resolves affected nodes through the compiled reverse dependency index and evaluates only that transitive set in topological order against one snapshot, instead of recomputing and rewriting every node (design: Drive evaluation from the reverse dependency index). Verify with an MQTT ingestion test asserting that a message for one metric leaves unrelated definitions' evaluation rows byte-identical, and that a two-level derived chain still updates in order.
- [x] 7.7 Make registry-backed aggregates respect page staleness policy on Factory Circuit: when a page sets `allowStaleRuntimeData` to false and any contributing slot reading is stale, the total-power KPI falls back with the same fallback reason and freshness as the slot cards built from those dependencies, rather than rendering the registry-computed number (design: Page staleness policy overrides registry aggregates). Verify with `displayStoryService.test.ts` covering the stale-slot case under both `allowStaleRuntimeData` settings.
- [x] 7.8 Make draft preview rejects malformed definitions with structured errors: the preview path runs the same structural validation as save before evaluating, so an incomplete draft body returns a structured client validation error naming the missing fields instead of an unhandled server error (design: Validate preview drafts before evaluating).
