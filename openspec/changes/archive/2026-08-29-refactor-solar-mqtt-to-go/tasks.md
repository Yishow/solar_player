> Remediation note: shared Config saves serialize snapshot/write/replace across factory services; remote-set mutation/save/rollback is held under one shared Config transaction lock with request-scoped 0600 pending snapshots committed only after ledger durability. Typed commit outcomes distinguish failed live rename (rollback + `PERSISTENCE_FAILED`) from successful rename with cleanup failure (keep accepted state, warn, manager-wide fail-closed); startup resolves all pending snapshots before control registration, retains them on disabled/unavailable/error ledger lookup, cleans only proven missing/rejected records, and fails closed on commit/cleanup errors. Accepted snapshots already equal to live config are cleanup-only, and ordered cross-factory pending recovery prevents stale overwrite. Unknown global broker/control/TLS credential keys are scrubbed by exact name while site login factory fields remain compatible; manager lifecycle owns a context-bound periodic processed-command purge; scraper URL diagnostics redact userinfo while retaining host/path, and secret-like type mismatch warnings omit raw values. Focused regression tests cover concurrent KN/CL updates, rollback interleaving, staged ledger-failure ordering, multi-factory startup recovery, deterministic purge ticks and shutdown, and log/error/debug URL redaction. Windows field/parity task 7.2 remains intentionally unchecked; task 9.2 is complete from the isolated Windows artifact witness.
